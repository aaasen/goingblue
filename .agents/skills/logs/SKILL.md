---
name: logs
description: Read Cloud Run logs for the going.blue gateway and codec services on Google Cloud
---

Going Blue is deployed on Google Cloud Run. There are two main services that we need logs from:
1. The gateway service. This handles incoming forecast requests and hands them off to the appropriate codec service. The gateway verifies that the forecast request has a valid token and codec version. It also handles quotas and writes request information to the database.
2. Codec services. There is a separate service deployed for each codec version. The codec service handles gathering forecast data from Open-Meteo and encoding it into a message. It replies to the gateway service with an encoded message which the gateway then sends back to the user.

A request can be tracked across both services using its `request_id`. This is a random UUID generated by the gateway service. Logs from each request are also grouped into a trace with `logging.googleapis.com/trace`.

The service's project and region are in `deploy.env` at the root of the repository. Never hardcode the project, region, or service name. Instead, source them before each command:

```bash
source deploy.env
```

The name of the gateway service is `$SERVICE`. The names of the codec services are `$SERVICE-codec-v<N>`. See `deploy.sh` for the current codec versions.

There are four types of logs:
 - App logs: one line of JSON per event from `log.ts`. Logs have fields `jsonPayload.<field>` and event names `jsonPayload.event` in the format `subject.verb`.
 - Request logs: one entry per HTTP request with `logName:"requests"`. These contain `httpRequest` but not `jsonPayload`. Request logs are generally not useful since there is a lot of scanner traffic to URLs that do not exist.
 - System logs: Google Cloud system logs at `run.googleapis.com/varlog/system` with a `textPayload`. It's generally not necessary to look at these logs.
 - Cloud SQL: Database logs at `cloudsql.googleapis.com/postgres.log`, `resource.type="cloudsql_database"`.

## Reading Logs

Use `gcloud logging read` to read logs. Always pass a `--limit` to avoid reading more logs than necessary.

See logs for both the gateway and codec services:

```bash
gcloud logging read \
  '(log_id("run.googleapis.com/stdout") OR log_id("run.googleapis.com/stderr"))' \
  --project "$PROJECT" --limit 50 --freshness 1d \
  --format 'value(timestamp,resource.labels.service_name,jsonPayload.event)'
```

Filter to just the gateway:

```bash
gcloud logging read \
  "(log_id(\"run.googleapis.com/stdout\") OR log_id(\"run.googleapis.com/stderr\"))
   AND resource.labels.service_name=\"$SERVICE\"" \
  --project "$PROJECT" --limit 50 --freshness 1d \
  --format 'value(timestamp,severity,jsonPayload.event)'
```

Filter to just the codec services:

```bash
gcloud logging read \
  "(log_id(\"run.googleapis.com/stdout\") OR log_id(\"run.googleapis.com/stderr\"))
   AND resource.labels.service_name:\"$SERVICE-codec\"" \
  --project "$PROJECT" --limit 50 --freshness 1d \
  --format 'value(timestamp,resource.labels.service_name,jsonPayload.event)'
```

Filter to only errors:

```bash
gcloud logging read \
  "severity>=ERROR" \
  --project "$PROJECT" --limit 20 --freshness 7d --format json
```

Filter by event type:

```bash
gcloud logging read 'jsonPayload.event="forecast.dispatch"' \
  --project "$PROJECT" --limit 20 --freshness 7d --format json
```

Filter to a single trace ID:

```bash
gcloud logging read "trace=\"projects/$PROJECT/traces/<TRACE_ID>\"" \
  --project "$PROJECT" --limit 100 --freshness 7d --format json
```

Filter to a single request ID:

```bash
gcloud logging read 'jsonPayload.request_id="<UUID>"' \
  --project "$PROJECT" --limit 100 --freshness 7d \
  --format 'value(timestamp,resource.labels.service_name,jsonPayload.event)'
```

Gateway request logs:

```bash
gcloud logging read \
  "log_id(\"run.googleapis.com/requests\") AND resource.labels.service_name=\"$SERVICE\"" \
  --project "$PROJECT" --limit 50 --freshness 1d \
  --format 'value(timestamp,httpRequest.status,httpRequest.requestMethod,httpRequest.requestUrl,httpRequest.latency)'
```

Request logs for serving forecasts:

```bash
gcloud logging read \
  'log_id("run.googleapis.com/requests")
   AND (httpRequest.requestUrl:"/forecast" OR httpRequest.requestUrl:"/sms"
        OR httpRequest.requestUrl:"/encode")' \
  --project "$PROJECT" --limit 50 --freshness 7d \
  --format 'value(timestamp,resource.labels.service_name,httpRequest.status,httpRequest.requestMethod,httpRequest.requestUrl,httpRequest.latency)'
```

## Forecast Request Logs

The saved query `forecast-request-path` shows only the logs relevant to a forecast request. It includes app logs from both the gateway and the codec services. It also includes request logs for relevant endpoints (`/forecast`, `/sms`, `/encode`). It does not include container lifecycle events.

```bash
gcloud logging read \
  '(log_id("run.googleapis.com/stdout") OR log_id("run.googleapis.com/stderr")
    OR (log_id("run.googleapis.com/requests")
        AND (httpRequest.requestUrl:"/forecast" OR httpRequest.requestUrl:"/sms"
             OR httpRequest.requestUrl:"/encode")))
   AND NOT (jsonPayload.event="server.listening" OR jsonPayload.event="db.schema_ready"
            OR jsonPayload.event="codec.listening")' \
  --project "$PROJECT" --limit 100 --freshness 1d \
  --format 'value(timestamp,resource.labels.service_name,jsonPayload.event,httpRequest.requestUrl)'
```

Editing the saved query is `gcloud logging saved-queries update forecast-request-path --location=global`. It is project-level and shared. Ask before updating it.
